# Story Builder — Issue Workflow

This document defines the repeatable, per-issue engineering flow for Story
Builder. It is agent-friendly: the `workflow-lead` opencode agent (and the
`/work-issue` and `/next-issue` commands) drive it, and the `scripts/` shell
tools perform the mechanical steps.

```
issue #N ──► acknowledge ──► implement (TDD) ──► test ──► independent review ──► PR ──► merge ──► next issue
                 │                                │            │                     │
             claim+label                     npm test      Gemini 3.8 (human-run, --yes)
             +worktree                       typecheck     read-only
                                             lint
```

## 0. One-time prerequisites

- **Node.js ≥ 20** and **npm**.
- **MongoDB** reachable at `MONGO_URI` (default `mongodb://127.0.0.1:27017`).
- **GitHub CLI**, authenticated once:
  ```bash
  gh auth login
  ```
  Every script that talks to GitHub checks this and tells you to authenticate
  if you have not.
- **opencode CLI** for the automated implement/review agents (already present
  in this environment). The reviewer model is `antigravity/gemini-3.8-flash-high`.

## 1. Provision an environment

```bash
scripts/workflow.sh setup            # .env + npm install + ensure MongoDB
scripts/workflow.sh setup --gen-secret --force-env   # reset .env with a random secret
```

`setup-env.sh` never overwrites an existing `.env` unless `--force-env` is given
(it backs the old one up first).

## 2. The per-issue loop

Issue numbers are **GitHub issue numbers** — the canonical identifier used in
branch names, commits, and PRs. Create them with the repo issue template:

```bash
scripts/workflow.sh new "Add character inventory system"
# -> created issue #12: https://github.com/harshil26r/story-builder/issues/12
```

Then run exactly the same flow for every issue:

| # | Stage         | Command                                                        | What happens |
|---|---------------|----------------------------------------------------------------|--------------|
| 1 | Acknowledge   | `scripts/workflow.sh ack <n>`                                  | Assigns you, labels `status:in-progress`, comments, creates worktree `../story-builder-worktrees/issue-<n>` on branch `issue/<n>-<slug>`. |
| 2 | Implement     | `/work-issue <n>` (or `/next-issue`)                           | `issue-implementer` agent does strict TDD in the worktree. No push/PR. |
| 3 | Test          | `scripts/workflow.sh test --dir <worktree>`                    | `npm test`, `npm run typecheck`, `npm run lint` (add `--full` for build). |
| 4 | Review        | `scripts/workflow.sh review <n> --dir <worktree>`              | `issue-reviewer` agent (**different model**: Gemini 3.8) reviews read-only; writes `.workflow/reviews/issue-<n>.md`. Exit 2 ⇒ `CHANGES REQUESTED`. |
| 5 | PR            | `scripts/workflow.sh pr <n> --dir <worktree> --commit feat`    | Pushes the branch and opens a PR whose body links the issue, lists changes, and embeds the review. |
| 6 | Merge         | `scripts/workflow.sh merge <n> --yes`                          | Human-run. Merges into `main`, fast-forwards local main, removes the worktree. |

### One command to drive a single issue

```bash
scripts/workflow.sh run 12 --auto          # ack → implement → test → review → PR
scripts/workflow.sh run 12 --to merge --yes # ...then merge
scripts/workflow.sh next                    # pick the oldest open issue and go
```

`--from` / `--to` let you resume partway (e.g. `--from test` after manual edits).

## 3. Agent roster (`.opencode/agent/`)

| Agent                 | Mode      | Model                              | Responsibility |
|-----------------------|-----------|------------------------------------|----------------|
| `workflow-lead`       | primary   | inherits your default              | Orchestrates the flow; delegates the two AI stages; stops before merge. |
| `issue-implementer`   | all       | inherits your default              | Implements one issue with strict TDD; cannot push/PR/merge. |
| `issue-reviewer`      | all       | `antigravity/gemini-3.8-flash-high`| Independent adversarial review; read-only. |

`mode: all` lets the two worker agents run both as delegated subagents and
directly via `opencode run --agent <name>` from the scripts.

Commands: `/work-issue <n>` and `/next-issue`.

> Config is loaded at startup. After editing anything under `.opencode/` or
> `opencode.json`, quit and restart opencode.

## 4. Conventions

- **Branches**: `issue/<n>-<slug>` (e.g. `issue/12-add-character-inventory-system`).
- **Commits**: `type(scope): summary`, `Refs #<n>` for the issue.
- **PRs**: one issue per PR; title = issue title; body generated by `pr-create.sh`
  and must include `Closes #<n>` plus the independent review.
- **Merging**: squash-merge into `main` by default; local `main` fast-forwards.

## 5. Artifacts & state

All local workflow state lives under `.workflow/` (git-ignored):

```
.workflow/
  issues/<n>/{title,branch,worktree,status,review,pr}
  reviews/issue-<n>.md            # clean review report (embedded in the PR)
  reviews/issue-<n>.md.full.jsonl # raw reviewer event stream (debug only)
  reviews/issue-<n>.md.full.err   # reviewer stderr
  pr/issue-<n>.md                 # generated PR description
```

Worktrees live **beside** the repo at
`${WORKTREE_ROOT:-<repo-parent>/story-builder-worktrees}/issue-<n>`, so they
never pollute the main checkout. Override with `WORKTREE_ROOT=/path`.

## 6. Troubleshooting

| Symptom | Fix |
|---------|-----|
| `GitHub CLI is not authenticated` | `gh auth login` |
| `cannot reach MongoDB` | start it (`sudo systemctl start mongod`) or run `setup --no-mongo` |
| `reviewer did not emit a recognised verdict` | inspect `.workflow/reviews/issue-<n>.md`; rerun `review` |
| Server suites fail: `Cannot find module .../bcrypt_lib.node` | npm ≥ 12 blocked install scripts. The repo's `allowScripts` allowlist covers this; if it drifts, run `npm install-scripts approve --all && npm rebuild`. |
| A model id is unavailable | `opencode models`; override with `REVIEWER_MODEL=provider/model` or `review --model` |
| Stale worktree | `git worktree remove --force <path>` then `git worktree prune` |
